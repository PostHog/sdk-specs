## Why

PostHog service PR [#90694](https://github.com/PostHog/posthog/pull/90694) adds top-level `property_matching_version` to local definitions and selects explicit equality only for version 2. The current SDK contract requires released legacy boolean truthiness unconditionally, so it would require incorrect results for v2 projects and loses the selector when definitions are cached.

## What Changes

- Select service legacy equality for missing/1 and explicit canonical equality only for exactly 2; other versions do not enable v2.
- Preserve legacy aggregate boolean truthiness and the empty-array exception; add the six distinguishing rows and complementary `is_not` fixtures, known-null/missing distinctions, normalization, and person/group/recursive-cohort propagation.
- Retain matching version with each complete definition snapshot through API projections, supported cache formats and hydration; preserve it on failure/304, reset on fresh omission, and invalidate evaluation results on version-only changes.
- **BREAKING** for SDKs whose existing missing/1 matcher already diverges from released service legacy (notably Ruby/Elixir): the target is service v1, not each SDK's historical behavior.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `local-feature-flag-evaluator`: versioned equality and stable matching context across evaluation paths.
- `flag-definition-loader`: versioned definition snapshots, cache round trips, and refresh semantics.

## Impact

Only these OpenSpec contracts and their private Gherkin acceptance fixtures change. Canonical specs are generated by archive/sync, not hand-edited. SDK implementations and harness adapters consume the resulting contract in their own repositories. Existing SDK compliance reports are not changed or certified by this work.

## Non-goals

No SDK implementation code, new test framework, dependency upgrades, remote `/flags` protocol changes, new cache backends, unrelated operator/number/Unicode rewrites, or changes to `flag_evaluates_to` comparison semantics.
